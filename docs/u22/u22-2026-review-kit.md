## Part 1. 一次審査向け ビルド&実行ガイド（審査員用 / 補足資料に転載可）

### 1.1 必要環境

| 項目 | 要件 |
|---|---|
| IDE | Android Studio（最新の stable 版を推奨） |
| JDK | **Android Studio 同梱 JBR（Java 21）必須**。システム JDK 25 以上は Gradle 8 系と非互換のため不可 |
| ビルドツール | Gradle 8.14.5（Wrapper 同梱、別途インストール不要） |
| SDK | compileSdk 36 / minSdk 26（Android 8.0）/ targetSdk 35 |
| ABI | **arm64-v8a のみ**（armeabi-v7a は同梱していません） |
| 初回ネットワーク | 依存解決のため Maven Central と JitPack（jitpack.io）への接続が必要 |

### 1.2 ビルド手順

```bash
# 1. ソースを展開してプロジェクトルートへ
cd Opedrgent

# 2.（Windows PowerShell の例）JBR を使用するよう JAVA_HOME を指定
#    macOS/Linux は Android Studio 内の jbr/Contents/Home を指定
$env:JAVA_HOME="C:\Program Files\Android\Android Studio\jbr"

# 3. Debug APK をビルド
./gradlew assembleDebug
```

成果物: `app/build/outputs/apk/debug/app-debug.apk`
素早くコンパイルだけ確認する場合: `./gradlew compileDebugKotlin`

> Sherpa-ONNX は JitPack 座標 `com.github.k2-fsa:sherpa-onnx:1.13.1` として Gradle が自動取得します。AAR を手動で配置する必要はありません（リポジトリ内の `app/libs/sherpa-onnx-1.13.2.aar` は旧ローカル運用の名残で、現在のビルドからは参照されていません）。

### 1.3 実行方法と、API キー／モデルが無くても動く範囲

- arm64-v8a の Android 8.0 以上の実機、または arm64 システムイメージのエミュレータで動作します。
- **API キーや端末内モデルが無くても起動し、以下はそのまま確認できます（純ローカル）**:
  - 画面遷移・各 UI、ノートとナレッジベースの作成・管理（Room / SQLite）
  - アマチュア無線「衛星パス予測」：SGP4/SDP4 軌道伝搬を端末内で数値計算、内蔵 16 衛星のデータベースを利用（ネット不要でも予測可能）
  - 内蔵 JS スキル（WebView サンドボックスでローカル実行）
- 以下を確認する場合のみ追加準備が必要です:
  - オンデバイス LLM（Gemma）／オフライン音声認識（Sherpa-ONNX）: アプリ内のモデル管理から端末へモデルをダウンロード
  - クラウド対話: OpenAI 互換 API キーを設定（任意。未設定でもアプリは動作）
- 審査用途では minify が有効な release ではなく、上記の **debug ビルドを推奨**します。

### 1.4 ビルドでよくある問題

- `Could not determine java version from '25'`: JDK が新しすぎます。Android Studio 同梱 JBR(21) を使用してください。
- Sherpa-ONNX 取得失敗: ネットワークが jitpack.io に到達できるか確認、必要ならプロキシを設定して再 Sync。
- `libonnxruntime.so` 重複: sherpa-onnx と onnxruntime-android が同名 .so を同梱するため、`packaging { jniLibs { pickFirsts += "lib/*/libonnxruntime.so" } }` で解消済みです。

## Part 2. ProtoPedia 登録項目（日本語原稿・コピペ用）

### ② 作品名（50文字以内）

```
Opedrgent — 声で自分を磨く、完全ローカルなAIエージェント
```

### ④ 作品概要（100文字未満）
```
自分の声を端末内で文字起こしし「理想の自分」との差を提示する批判鏡を核に、オンデバイスLLMと15種超のツールを自律実行する、ネット無しでも動くAndroidのAIエージェントです。
```

### ⑩ システム構成（テキスト）
```
【実行端末】Android 8.0(API26)以降 / arm64-v8a
【UI】Kotlin + Jetpack Compose(Material3)
【オンデバイスLLM】LiteRT-LM 0.12（Gemma）+ TFLite、GPU/NPU 加速
【オフライン音声認識】Sherpa-ONNX(Paraformer/SenseVoice)、MiMO ASR、Android SpeechRecognizer の自動フォールバック
【クラウドLLM(任意)】OpenAI 互換 API（設定しなくてもローカル機能は動作）
【エージェント層】ToolRegistry が 15 種超のツール（Web検索/URL取得/JSサンドボックス/Intent/カレンダー/Health/衛星軌道計算など）を動的に実行
【全二重音声】AudioRecord/AudioTrack + ハードウェアAEC + VAD + BargeIn、5状態FSM
【ローカル記憶】Room / SQLite / DataStore / EncryptedSharedPreferences
【衛星通信】SGP4/SDP4 軌道伝搬、Celestrak/AMSAT から TLE 取得（オフライン時は内蔵DB）
```
（⑨には、この構成を図にしたシステム構成図を1枚登録してください。）

### ⑬ 登録内容（本文）

#### 【制作背景】
人は自分の言動を客観視できません。「自分は丁寧で尊重深い」と思っていても、録音を聞き返すと相手を遮ったり高圧的だったりする——そのギャップに気づくには、自分の発話を記録し、冷静に映し返す仕組みが必要です。しかし最も私的な「自分の声と内省」をクラウドAIに送るのは不安が残ります。そこで、**音声認識も言語モデルも端末内で完結し、データを外に出さずに自分を磨けるAI**を作りたいと考えました。

#### 【作品概要詳細】
Opedrgent は、①オンデバイス LLM とオフライン音声認識による完全ローカル基盤、②LLM が 15 種を超えるツールを自律的に呼ぶエージェント機構、そして③自分の発話を「理想の自分（利用者が定義する行動基準）」と照合して差分と具体的な言い換えを返す「批判鏡（自己修練）」を中核とする Android アプリです。対話・深い調査・知識洞察・全二重インタビュー・議事録、さらにアマチュア無線の衛星パス予測と ADIF ログまでを1本に統合し、ネットが無い環境でも主要機能が動きます。

#### 【実装した内容】（すべて実装済み）
- **批判鏈（自己修練）**: 本人の音声書き起こしを、利用者が定めた理想の人格行動基準と逐語的に照合。問題箇所は原文を引用して根拠を示し、人格を否定せず行動に絞って、次に使える言い換えを提示。自己否定時は支援を優先。
- **マルチエンジン音声認識**: Sherpa-ONNX（オフライン）→ MiMO ASR → Android 標準の自動フォールバック、話者分離と複数人議事録。
- **全二重インタビュー**: AEC/VAD/BargeIn と 5 状態 FSM、目標アンカーと逸脱検出を持つ「海馬記憶」。
- **ツール呼出エージェント**: 検索・URL取得・深い調査（ハイブリッドランキング）・JS サンドボックススキル・Intent・カレンダー・Health など15種超。
- **知識洞察エンジン**: 要点抽出→分野横断の関連付け→核心洞察→金句、の4段階をタグ→索引→詳細の3層漸進コンテキストで実行。
- **衛星通信**: SGP4/SDP4（J2/J3/J4 摂動、大気抵抗、深宇宙 SDP4）、16衛星の内蔵DBと多源 TLE、ADIF 3.1.4 書き出し。
- **プライバシー**: ローカル推論・暗号化保存を基本とし、クラウド API は利用者が任意で選択。

#### 【アピールポイント】（既存サービスとの違い）
1. **完全ローカル**: 多くの AI アシスタントがクラウド前提なのに対し、ASR も LLM も端末内で動き、最も私的な内省データを外部に送らない。圏外でも動く。
2. **チャットbotではなく実行するエージェント**: 対話だけでなく、検索・調査・端末機能・軌道計算までツールとして自律実行。
3. **「自分を映す」という独自用途**: 意見を押し付けず、お世辞も言わず、逐語証拠に基づいて言動の差分と代替案を返す「批判鏡」は、自己成長・面接練習・人間関係・指導の振り返りに使える。

#### 【一番のこだわり】
「データを外に出さない」ことと、「批判鏡は甘やかさないが、人を否定しない」ことです。クラウドが当然視される時代にあえて端末内完結にこだわり、安心して自分の声を残せる場を作りました。そして批判鏡は、感情的な非難や単語への機械的な判定をせず、必ず発話の原文証拠に基づき、行動レベルの改善と具体的な言い換えまで提示する設計にしています。

#### 【こだわりを実装するために苦労・工夫した点】
- 貧弱な端末 LLM でも破綻しないよう、知識洞察をタグ→索引→詳細の**3層漸進コンテキスト注入**にしてトークンを節約。
- オフライン ASR を止めないため、3エンジンの自動フォールバック鎖を構成。
- 全二重音声の割り込み・エコーを、ハードウェア AEC と VAD/BargeIn、5状態 FSM で安定化。
- sherpa-onnx と onnxruntime が同梱する `libonnxruntime.so` 衝突を pickFirst で解消し、arm64 単一 ABI に絞って再現性を確保。
- ネットワーク層に熔断・レート制限・多重キャッシュ・適応的並行制御を自前で実装。

#### 【今後の展望】（未実装・構想）
- 理想の人格基準の初期テンプレートと、長期の言動トレンド可視化。
- 「歴史上の模範者なら同じ場面でどう振る舞うか」を複数視点で提示するモード。
- SDR（ソフトウェア無線）との連携強化と多言語対応。
