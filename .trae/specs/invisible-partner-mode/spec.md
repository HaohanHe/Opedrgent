# 无感伙伴模式 (Invisible Partner Mode) Spec

> **叙事主线：你说过的话，会变成礼物回到你手上。**

## Why

Opedrgent 当前是一个**瑞士军刀**——功能齐全但每个功能都要用户主动触发、主动点击、主动等待。用户要录音→停止→转写→**手动点保存**；要发芽→选笔记→**手动点发芽**→等；要看历史→**手动打开管理页**。

得到大脑发布会的核心启示是：**AI 不应该是工具，应该是伙伴。工具等你叫，伙伴主动接。**

罗振宇原话：
> "AI 的算力不会再值钱，甚至会无感，他就会陪伴在我们这儿。"
> "你的行为应该触发对你有善意的智能行动。"

本 Spec 的目标是让 Opedrgent 从"你找 AI"变成"AI 找你"。

---

## 设计哲学（三视角交叉验证）

### 心理学家视角：人记东西是想被看见

用户打开 App 录一段话，他真正想要的不是一个笔记。他要的是**有人听见**。

录音结束那一刻，用户的心理期待是："我说完了。有人在吗？"

现在的回答是：`"已保存。"（冷冰冰的系统确认框）`
应该变成：`"我听见了——你说的这段关于 XX 的话，有个地方挺特别的……"`

**关键洞察："无感"不应该是设计目标。"恰到好处的存在感"才是。**
- 用户不需要感知存储过程
- 但必须感知到"被记住"这件事本身

### 人类学家视角：外化记忆需要信任回应

人类学概念"延伸心灵"（Extended Mind, Clark & Chalmers 1998）：人的认知在笔记本、手机等外部媒介上延续。每一次外化都伴随信任关系——可靠性、可回溯性、**回应性**。

Opedrgent 前两条做得不错（SQLite + 海马体搜索），但第三条**回应性**几乎为零。
存了就存了，沉默。像一个记忆力极好但面无表情的秘书。

**关键洞察：发芽+推送要有"时序仪式感"。**
- 发芽 → 夜间静默执行（用户睡觉时干活）
- 推送 → 次日早上送达（用户醒来时发现礼物）
- 像圣诞老人，不是快递员

### 叙事学家视角：产品必须在用户身上完成完整故事弧线

| 叙事节拍 | 用户状态 | 产品角色 |
|---------|---------|---------|
| **日常世界 (Before)** | 脑子快溢出了，好想法散了会就忘 | — |
| **冒险召唤 (Call)** | 鼓起勇气录了一段话 | 必须接住，不能让用户在第二拍流失 |
| **深渊考验 (Ordeal)** | 已付出注意力成本 | 必须回报以价值：输入碎片→输出宝石 |
| **回归携宝 (Return)** | 带着收获回到日常 | 次日推送 = 第四拍延续 + 下一轮第一拍的开始 |

**关键洞察：功能清单不够，需要一条叙事主线贯穿所有设计决策。**

---

## 核心原则：三条无感原则（修订版）

| 原则 | 定义 | 对标 | 修订 |
|------|------|------|------|
| **记录即遗忘** | 用户产生内容的瞬间就已完成存储，零额外操作 | 得到大脑"颗粒归仓" | 不是为了方便，是为了"不错过你的任何一句话" |
| **伙伴会敲门** | 有价值的产出自动推送到用户面前 | 得到大脑每日回顾 | 夜间干活/晨间送达，像圣诞老人送礼物 |
| **被看见才会上瘾** | 每次记录都获得有温度的正反馈 | 得到大脑"点评" | 必须引用原文具体词句，证明"我真的听了" |

## What Changes

### 1. 零交互录音链路 (Record-and-Forget)
- 录音结束后**自动转写 → 自动存笔记 → 自动入海马体**
- 去掉"保存笔记"按钮，或保留但标记为"可选操作"（仅用于编辑标题/分类）
- 转写完成后发送一条轻量级通知：
  - ❌ `"已为你记下这段话（32字）"` （账单式）
  - ✅ `"记下了——你开头说的那句'XX'，我先帮你收着了"` （回应式）
- 通知点击可展开查看全文 / 编辑 / 删除

### 2. 自动发芽引擎 (Auto-Sprout Engine)
- 新增后台定时任务（WorkManager），每天固定时间扫描当天新内容
- **时序设计（仪式感）**：
  - 执行时间：默认 23:00（用户大概率已放下手机）
  - 推送时间：次日早 8:00（不是执行后立即推）
  - 两步分离：Worker 先静默执行 + 存库 → 定时器次日晨间推送
- 筛选策略：优先处理有足够长度的新笔记 / 未发芽的对话记录，每天最多 3 篇
- 推送文案：
  - ❌ `"你的发芽报告已生成"` （工具语言）
  - ✅ `"昨晚你说的那段关于 XX 的话，展开后是这样的……"` （礼物语言）
- 支持用户在设置中配置开关 / 时间 / 频率

### 3. 每日回顾推送 (Daily Digest / "每日收获")
- 每天早上推送一条通知（可配置，默认 8:00）
- 内容从海马体索引中捞取昨天的精华：
  - 昨日新增笔记数
  - 最长的一条摘要（引用原文片段，不是概括）
  - 如果有未读发芽报告，提示查看
- **这不是账单，这是礼物包装纸。** 通知语气要温暖、具体、有个人感
- 点击通知打开 App 的首页或专用回顾页

### 4. 温暖点评 (Warm Feedback / "点评")
- 每次**笔记保存成功后**，异步调用 LLM 生成一句点评
- 点评规则（写入 system prompt）：
  - **必须引用原文的具体词句或短语**（证明真的读了）
  - 先肯定整体感受
  - 再挑一个最值得展开的点（用原文的话来锚定）
  - 不批评、不打分、不给建议列表
  - 控制在 50 字以内
- 示例对比：
  - ❌ 工具型：`"这段关于多agent协作的思考挺有意思。"` （正确但空洞，可以用在任何笔记上）
  - ✅ 伙伴型：`"你今天提到'免贵工具的直白态度'——这个词用得很准，像是在说某种技术价值观。"` （只有这条笔记能产生这个点评）
- 展示方式：snackbar 替代原有 toast "已保存"；或在笔记详情页顶部显示折叠点评条

### 5. 海马体隐形化 (Hippocampus as Infrastructure)
- 海马体从"用户可见的管理界面"降级为"纯后台基础设施"
- 设置中的入口移到深处（设置 → 高级 → 数据管理）
- 所有搜索/发芽/每日回顾功能内部使用海马体，但用户不感知其存在
- HippocampusScreen 保留给高级用户

## ADDED Requirements

### REQ-AF-1: 零交互录音保存
系统 SHALL 在语音录音完成并转写结束后，**无需用户额外操作**自动将转写文本保存为笔记并存入海马体索引。

**场景：用户录完一段话**
- **WHEN** 用户在录音页面停止录音且 ASR 转写完成
- **THEN** 系统自动创建笔记（标题取前20字）、保存到数据库、索引到海马体
- **AND** 显示一条**回应式通知**（引用原文内容而非仅显示字数）
- **AND** 用户仍可在通知中编辑标题或删除该笔记

### REQ-AF-2: 自动发芽调度（两阶段时序）
系统 SHALL 提供后台定时发芽能力，采用**夜间执行+晨间推送**的两阶段时序。

**场景 A：夜间静默执行**
- **WHEN** 到达用户设定的执行时间（默认 23:00）
- **THEN** AutoSproutWorker 选取当天最多 3 篇未发芽的新内容执行发芽
- **AND** 发芽报告持久化到 SproutReportStore（**不推送通知**）

**场景 B：晨间送达**
- **WHEN** 到达用户设定的推送时间（默认次日 8:00）
- **THEN** DailyDigestNotifier 读取昨夜发芽结果，推送**礼物式通知**
- **AND** 通知文案包含原文引用片段，非通用模板

### REQ-AF-3: 每日回顾推送
系统 SHALL 每天早上推送一条"昨日收获"通知。

**场景：早间推送**
- **WHEN** 到达用户设定的推送时间（默认 8:00）
- **THEN** 从海马体索引查询昨日数据，聚合为 digest
- **AND** 通过 NotificationManager 推送样式化通知
- **AND** 通知包含：昨日笔记数 + 一条精选原文片段 + 未读发芽报告数
- **AND** 通知文案风格为"礼物包装"而非"数据账单"

### REQ-AF-4: 温暖点评反馈（引用原文式）
系统 SHALL 在每次笔记保存后，异步生成一句**引用原文具体词句**的点评。

**场景：笔记保存后**
- **WHEN** 笔记成功写入数据库
- **THEN** 异步调用 WarmFeedbackService 生成点评（< 50 字）
- **AND** 点评 MUST 包含笔记原文中的至少一个具体词句或短语作为锚点
- **AND** 以 snackbar 展示，替代原有的"已保存"toast
- **AND** 点评格式：先肯定 + 引用原文挑亮点，不含批评或建议列表

### REQ-AF-5: 无感模式设置面板
系统 SHALL 提供统一的无感模式设置入口。

**场景：用户调整自动化程度**
- **WHEN** 用户进入设置 → 无感伙伴模式
- **THEN** 显示以下开关/选项：
  - 录音自动保存（开/关）
  - 自动发芽（开/关 + 执行时间选择）
  - 晨间推送（开/关 + 推送时间选择）
  - 温暖点评（开/关）

## Implementation Notes

### 技术选型
- **定时任务**: Android WorkManager（兼容 Doze 模式）
- **本地通知**: NotificationManager + NotificationChannel
- **点评生成**: 复用 LlmClient，轻量 prompt（max_tokens=100, temperature=0.9）
- **批量发芽**: SproutService.sproutBatch() 并发限制=2

### 性能约束
- 自动发芽每天最多 3 篇，控制 token 消耗
- 点评生成 3 秒超时保护，不阻塞主流程
- 每日 digest 纯本地聚合，不调 LLM

### 用户体验红线（叙事连贯性）
- **永远不要阻塞用户操作**：所有自动化都是异步后台进行
- **永远可以关闭**：每个自动化功能都有独立开关，一键全部关闭
- **通知不能骚扰**：每天最多 2 条推送（点评不算，点评是内联展示）
- **每条通知都必须有"礼物感"**：引用原文、具体、不可互换
- **时序即仪式**：夜间执行 / 晨间送达，不在用户忙碌时打扰

### Prompt 设计指南（点评）
点评 prompt 的核心指令：
```
你是一个认真倾听的朋友。用户刚写下一段文字，你要给他一句简短的回应。
规则：
1. 必须从原文中找出一个具体的词、短语或句子直接引用（加引号）
2. 先表达你对整体的感受（一句话）
3. 用引用的那个点说明为什么它有意思
4. 不批评、不打分、不给建议列表、不说"你可以试试"
5. 50 字以内
6. 不要用感叹号
7. 不要说"很棒""不错""精彩"这种空话

示例输入："今天开会讨论了多agent协作的问题，我觉得免贵工具的直白态度其实是一种技术价值观的体现"
示例输出："你提到的'免贵工具的直白态度'——把免费和价值观连在一起想，这个角度很少见。"
```

## 用户洞察（跨人群需求分析）

### 核心发现："无感"对不同的人意味着完全不同的事

| 用户画像 | 核心动机 | 要温暖吗 | 要效率吗 | 要分享吗 | 点评疲劳风险 |
|---------|---------|---------|---------|---------|------------|
| 80岁老人(张爷爷) | 抗遗忘、尊严感 | 极其要 | 不要 | 给家人看 | 低 |
| 13岁孩子(小林) | 找人听、树洞 | 极其要 | 不要 | 不要 | 中 |
| 35岁产品经理(李姐) | 省时间、外包整理 | 不要 | 极其要 | 给同事 | 高 |
| 22岁创作者(阿文) | 不打断灵感 | 看情况 | 中等 | 可能 | 中 |
| 45岁医生(王医生) | 不出错、安全 | 不要 | 极端要 | 不能 | 极高 |
| 28岁妈妈(小周) | 留住瞬间 | 要 | 不要 | 极其要 | 低 |

### 结论：同一套基础设施 + 三套交互层（多人格模式）

底层共享：HippocampusIndex + AutoSproutWorker + NotificationHelper + WarmFeedbackService
上层根据模式切换：文案风格 / 功能开关 / 推送策略 / 点评 prompt

| 功能 | 生活模式(Life) | 工作模式(Work) | 创作模式(Creative) |
|------|---------------|----------------|-------------------|
| 目标用户 | 老人/孩子/妈妈 | PM/医生/职场人 | 写作者/思考者 |
| 点评 | 引用原文式温暖回应 | **关闭** | "和你 X 月 Y 日的笔记有关联" |
| 发芽 | 叙事式报告 | 结构化决策提取 | 灵感展开+写作建议 |
| 推送 | "昨日收获"+周年纪念 | "今日待办汇总" | "未展开的灵感 N 条" |
| UI 文案 | 收获/种子/礼物 | 摘要/行动项/决策 | 灵感/素材/草稿 |
| 分享 | 家庭群优先 | 同事/文档优先 | 社交平台/发布 |

### 发芽报告后续操作缺口（P0）
当前发芽报告是终点——看完就没了。需要变成起点：
- 追加笔记（基于发芽内容继续写）
- 添加标签/分类到知识库
- 分享（微信/家庭群/文档）
- "基于此继续深挖"（二次发芽）

### 点评疲劳防护（P0）
任何重复性正反馈都会边际递减：
- 点评必须关联历史（"你上周也提到过 XX"）才能持续新鲜
- 不同模式不同点评策略
- 生活模式：情感共鸣；工作模式：关闭或极简确认；创作模式：连接提示

### 周年回顾/时光胶囊（P1）
对生活记录者（老人/妈妈），最高价值的推送不是每日摘要而是：
- "一年前的今天，你录下了……"
- "这条录音已经保存了 N 天"
- 需要标记机制：用户可标记某条记录为"重要时刻"

## ADDED Requirements (Phase 2)

### REQ-P2-1: 多人格模式 (Partner Persona)
系统 SHALL 提供三种使用模式切换，每种模式调整全套交互层。

**场景：用户选择使用模式**
- **WHEN** 用户在无感伙伴模式设置中选择模式（Life/Work/Creative）
- **THEN** 全套功能按模式配置自动调整：
  - 点评 prompt 切换（温暖/关闭/连接型）
  - 发芽 prompt 切换（叙事/结构化/灵感型）
  - 推送文案模板切换
  - UI 显示文案切换
- **AND** 模式选择持久化到 DataStore

### REQ-P2-2: 发芽报告后续操作
发芽报告展示页 SHALL 提供操作入口。

**场景：查看发芽报告后**
- **WHEN** 用户正在查看 NoteSproutScreen 的发芽报告
- **THEN** 底部显示操作栏：
  - "追加笔记" — 将发芽内容作为新笔记保存
  - "分享" — 分享发芽报告文本（Android ShareSheet）
  - "基于此再发芽" — 以当前发芽结果为种子二次深挖
- **AND** 三点菜单中额外提供：添加标签 / 复制全文 / 导出 Markdown

### REQ-P2-3: 点评上下文感知
点评生成 SHALL 关联用户历史记忆。

**场景：生成点评时**
- **WHEN** WarmFeedbackService.generateFeedback() 被调用
- **THEN** 除传入的 noteContent 外，额外查询 HippocampusIndex：
  - 取最近 3 条同 scope 的历史记录摘要
  - 检查是否有语义相似的历史内容（关键词重叠 > 30%）
- **AND** 如果找到关联历史，点评 prompt 中注入上下文提示：
  `"用户之前也提到过类似的：[历史片段]。如果可以自然地建立联系，请提及。"`
- **AND** 如果没有关联历史，使用标准点评 prompt（不强制关联）

### REQ-P2-4: 周年回顾推送
系统 SHALL 在用户有历史记录的日期推送周年提醒。

**场景：重要日期回顾**
- **WHEN** DailyDigestNotifier 每日执行时
- **THEN** 额外检查 HippocampusIndex 中是否有 N 年前（N=1/2/3）同日的记录
- **AND** 如果有，在每日推送中附加一条："N 年前的今天：[原文片段]..."
- **AND** 点击可跳转到该条历史记录详情
